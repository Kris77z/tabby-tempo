# 本地真实双模型闭环验收 · 2026-10-12

本机 Next 生产构建 → 真实签名登录和托管 API → Anvil 合约 → Magpie → Kimi K2.6 / Kimi K3 → Pi 公开样例 → 独立 Docker Arena 隐藏测试 → 链上结算已打通。自主规划器实际选择了两次信用融资，连续完成两单并达到次数上限后停止。

本轮没有部署云服务或提交 Monad 交易。Anvil 身份注册表与 USDC 是测试合约，供应商模型调用是真实请求。游戏支路保留已有验收，本次没有新开真实模型游戏局。浏览器注入的是独立本地验收钱包，只签登录挑战，所有 HTTP 都访问真实服务。

## 成功路径

金额均为测试 USDC，6 位小数；每单额度包 0.12，报酬 0.15。

| 路径 | 现金支付 | 借款本金 | 偿还本金与费 | 最终 cash | 信誉 |
| --- | ---: | ---: | ---: | ---: | --- |
| K2.6 单次任务 #1 | 0.04 | 0.08 | 0.092 | 0.058 | 500 → 570，C |
| K3 单次任务 #2 | 0.04 | 0.08 | 0.092 | 0.058 | 500 → 570，C |
| 自主第 1 单 #4 | 0.04 | 0.08 | 0.092 | 0.058 | 500 → 570，C |
| 自主第 2 单 #5 | 0.048 | 0.072 | 0.0828 | 0.0672 | 570 → 640，B |

自主 Agent 初始 cash 为 0.05。每次规划先支付 0.01；两次决策均由真实 K2.6 返回 `run-task / kimi-k2.6 / credit`，费用合计 0.26（两份包价加两次规划）。四单都通过独立判题，四笔贷款都已还清；自主 Agent 的两次实际还款与声誉镜像均为 2，违约为 0。

K2.6 单次任务实际输入190、输出45，扣280微额度；K3 输入334、输出95，扣1572微额度。差异来自不同输入/输出费率（1/2 与 3/6）和实际 usage。两个包价相同，不把运营包价或微额度账本冒充供应商逐 token 账单。

## 真实故障与修复

1. Next 将 URL 中的127.0.0.1规范化为localhost，合法来源被误拒。代理现在接受这一个框架规范化行为，原始 Host/Origin 仍严格校验；真实生产 challenge 通过，错误来源仍拒绝。
2. 1024-token 任务误入仅支持512-token 的游戏奖励适配器，购买前停止。现在奖励策略不适配时保留原推理上限，转入额度购买；调用前错误保存为可恢复暂停，不再伪装成模型响应失败。第一次无模型调用的开发运行保留在 `runtime-admission-failure`。
3. 规划器原先缺少包价，选择了资金不足的现金方案。现在输入包含规划费、扣费后余额、包价、现金优先的信用缺口、借款费及模型费率；不强制模型或融资选择。新的自主信用两单真实通过。
4. 自主父任务暂停后不能充值。现在后端从可信父子记录解析当前任务并验证身份，充值保留父预算，完成后恢复原钱包占用；前端同步开放这一补资入口。受控实际链回归验证同 child 完成与重复恢复不二付。
5. 前一条真实自主现金请求在调试期间超过五分钟报价期限。充值虽成功，旧 Anvil latest block 时间滞后导致晚付款，Relay 正确拒绝交付。通过原 paymentId 和固定 refundId 退回0.12；原父请求终结为 `Failed / REFUNDED`，只保留已交付规划费0.01，cash为0.12、债务0、信誉500，没有伪造任务成功。SDK新增签名与广播前的链时钟/本地时钟联合检查；已确认付款仍可继续核对。

总共7次真实供应商请求：4次求解、成功自主循环2次规划、旧失败分支1次规划。没有为制造修复记录而故意让模型出错。原 UUID 重放前后供应商请求数保持7，四个托管钱包交易 nonce不变。
