# Tempo 付款与 Goal 恢复修复：PR 范围和验收

本次主 PR 收录产品修复与纯离线回归，准备为 draft；不合并、不部署，不恢复任何旧业务窗口。真实完整流程仍未验收通过，尤其不能把合成游戏奖励和退款恢复结果当成真实模型、自然获奖及奖励任务完整恢复的证明。

## 产品行为

- SDK 将明确的暂停、取消和截止控制信号与付款未知分开，保留原 handle 和有限安全 cause。已签名或广播结果不明时仍不得新建付款；已交付缓存不触发新的派发准入。
- Goal 向独立评审提供经过绑定校验的外部付费文本交付证据，并在冷恢复时重新核验 canonical proof。证据不代表任意浏览、工具或代码执行，也不能使错误内容通过评审；已签名历史 prompt 的 digest 不重写。
- Relay 启动只核账，不把重启当成模型派发授权；分页失败不越过未完成范围，恢复继续使用原付款游标与 canonical 校验。默认扫描配置不变。
- Underwriter 将授权本金限制在协议每周期上限内。封存的未使用自动游戏 parent 不能重新准入；runtime 封存配置保持原生字段顺序，避免仅格式变化破坏严格字节守卫。

## 离线回归与 CI

测试只使用独立本地 Anvil、loopback 合成模型和本地 Docker/Arena，私钥与状态均由 fixture 生成。覆盖付款前及付款后暂停、原 handle 冷恢复、广播响应丢失、缓存不重复派发、退款和取消幂等、38 块查询分为 10/10/10/8、失败页游标保留、独立外部交付评审、错误内容拒绝及无奖励停止。

本地定向回归 32/32、类型检查和离线合约构建通过；root 独立配置/封存回归 22/22、付款/冷恢复回归 13/13 通过；后者与本地 32 项有覆盖，不相加为去重总数。

现有 `npm run test:all` 会通过 workspace 测试 glob 收集新增产品回归；现有 Tempo CI step 另运行 runtime/config/features 测试，无需新增 live CLI 执行步骤。类型检查使用 `npm run typecheck`。审查记录应附实际命令、退出码和源码摘要；本地定向通过后，draft PR 仍需完整 GitHub Offline checks 与人工审查。

不收录隔离 live driver、历史用户批准常量、钱包/授权/journal、私密 `.data`、真实 RPC 响应 fixture、代理 transport 或历史运行报告；不把旧批准作为新授权。所有旧窗口及封存证据留在原位置。

本次没有改生产配置文件、合约、Alchemy 业务 RPC、模型或代理默认路由，也未访问 VPS。TLS 前断连的具体远端原因仍未定位，这个 PR 不声称修复网络。任何后续真实运行仍须独立方案、费用授权和执行前门禁；不得自动合并或部署。
