## 独立验收时限修复

首轮失败的 Pi 记录显示正确候选通过公开样例，但 Arena 判为失败并清算。进一步用受控 Docker 启动延迟确定性复现：启动等待超过代码时限时，旧执行器会把正常的 `print(9)` 判为代码超时。原失败未保存完整隐藏测试诊断，因此不将这项复现声称为对那两次失败的逐项溯源。

修复后，可信启动信号发出后才计算代码执行时限；信号不能通过提交代码重放来重置。运行时限届满还会核对 Docker daemon 的自有容器状态，只有仍在运行才按代码超时处理。启动或 attach 状态不确定会抛出基础设施错误，不签发失败判定，不罚没借款。容器删除移至执行结果核对之后，并保留清理检查。
